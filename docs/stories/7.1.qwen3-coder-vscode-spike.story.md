## User Story

**As** owner-operator do servegate procurando reduzir dependência do Anthropic Claude Code e ter fallback local pra coding agentic,
**I want** um segundo modelo (Qwen3-Coder-30B, Apache-2.0) servido via `gemma4-gateway.jhonata-matias.workers.dev/v1/chat/completions` — selecionável por `model: "qwen3-coder:30b"` — acessível no VS Code via Copilot BYOK com tool-calling habilitado, cobrindo todas as buckets de complexidade T1-T5 do meu workflow real,
**so that** posso rodar tasks do meu backlog (analisado empiricamente: 98 PRs / 14 dias do repo `contabhub/onety`, distribuição T1 14% · T2 27% · T3 24% · T4 30% · T5 6%) no modelo local com harness de test suite como salvaguarda anti-alucinação, escrever memo de outcome em 30 dias, e decidir go/kill via ADR-0007 baseado em métrica objetiva de `% PRs migrados`.

## Context

### Why this story exists now

Owner completou (sessão 2026-07-25) três blocos convergentes que destravaram esta spike:

1. **Fix do gateway pro OpenAI compat** (deploy prod `c737cd5c`) — `/v1/chat/completions` funcional em prod, testado end-to-end com gemma4:e4b. Padrão pronto pra receber segundo modelo.
2. **Análise empírica de custo** (PM analysis 2026-07-25) — sample de 98 PRs no repo `contabhub/onety` mostra: 41% dos PRs são T1+T2 (30B-model confiável), 24% T3 (usável com iteração), 36% T4+T5 (owner aceitou risco explicitamente com harness dev como mitigação). Cenário híbrido projeta economia de $3-70/mês vs Anthropic 100%, mas ganho principal é redundância anti-outage + trabalho offline.
3. **Discovery de infra**: pod persistente `xzn1mf6skopp5m` tem GPU não confirmada (Q1 brief pendente desde 2026-07-02); Network Volume 150GB `mqqgzwnfp1` já provisionado (US-IL-1), zero custo incremental de storage.

O brief original ([`docs/brief-agentic-coding.md`](../brief-agentic-coding.md)) locou escopo em **CLI-only via SSH tunnel**. Este spike **amplia** para VS Code BYOK via gateway — mudança de escopo autorizada pelo owner na sessão 2026-07-25, formalizada aqui. Amendment ao brief deve ser feito por `@pm` em ciclo posterior.
